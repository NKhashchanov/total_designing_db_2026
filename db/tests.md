# Тестирование FoodExpress

SQL-сценарии проверяют структуру, целостность, операции и права доступа. Проверки выполняются в выделенной базе PostgreSQL 17 с тестовыми данными. Сценарии соответствуют [спецификации проверок](../templates/tests.md).

## Порядок проверки

Установить схему или восстановить резервную копию по [руководству по развертыванию](docs/getting-started.md). Выполнить основные, граничные и нагрузочные сценарии в выделенной базе. После восстановления архива повторить основные и граничные сценарии в восстановленной базе.

SQL-тесты выполняются под ролью `inspector` через `set role`, проверяют инварианты и откатывают тестовые изменения. При нарушении инварианта сценарий вызывает `raise exception`; выполнение останавливается на первой ошибке.

Ожидаемые сообщения при успешном завершении:

```text
SMOKE_OK
EDGE_CASES_OK
PERFORMANCE_OK
```

## Отдельные сценарии

Для установленной базы PostgreSQL 17 выполнить из корня репозитория (подключение с административной ролью, способной выполнить `set role inspector`):

```bash
psql -h 127.0.0.1 -U postgres -X -d foodexpress -v ON_ERROR_STOP=1 -f db/tests/smoke.sql
psql -h 127.0.0.1 -U postgres -X -d foodexpress -v ON_ERROR_STOP=1 -f db/tests/edge_cases.sql
psql -h 127.0.0.1 -U postgres -X -d foodexpress -v ON_ERROR_STOP=1 -f db/tests/performance.sql
```

Для проверки восстановленной базы указать `foodexpress_restore` вместо `foodexpress`. Для проверки входа по паролю использовать `psql -h 127.0.0.1 -U inspector -d foodexpress -W` при настроенной парольной аутентификации.

## Диагностика ошибок

| Проблема | Действие |
|---|---|
| SQL-сценарий завершился с ошибкой | Найти первое сообщение ERROR, проверить имя ограничения или процедуру и соответствующий BR в constraints.md |
| Нет SMOKE_OK или EDGE_CASES_OK | Проверить код выхода сценария и сообщения RAISE EXCEPTION; повторить сценарий после исправления |
| Не совпадает количество записей | Проверить исходное состояние таблиц и параметр value; повторные вызовы генератора добавляют данные |
| Ошибка прав | Проверить SET ROLE, search_path и grants.sql; прямой вход по паролю проверять отдельно |
| Не совпадает план EXPLAIN | Сравнить объем данных, статистику и настройки PostgreSQL; форма плана и время не являются фиксированными |
| Ошибка отложенного ограничения | Проверить состав заказа, суммы и платежи на момент COMMIT или SET CONSTRAINTS ALL IMMEDIATE |

При ошибке незавершенная транзакция откатывается при закрытии соединения. Изменения схемы и операций вносятся в SQL-файлы, из которых создается резервная копия.
