# Операции FoodExpress

Объекты находятся в схеме `mineev_food`. Перед выполнением примеров установить `set search_path to mineev_food, exts;`.

## Добавление блюда — FOOD-104

```sql
call add_product(p_restaurant_id, p_product_category_id, p_name, p_price,
                 p_rating, p_status, p_description, p_photo_url);
```

Параметры в примере обозначают значения соответствующих типов. Процедура проверяет ресторан, категорию, цену и рейтинг; UUID создается автоматически. Фото может отсутствовать. Параметр `p_rating` предусмотрен контрактом, но без отзывов рейтинг нового блюда равен NULL (BR-9.7). Если передан ненулевой рейтинг, процедура сообщает об этом через NOTICE.

## Генерация и очистка — FOOD-102, FOOD-103

```sql
call insert_test_data(10);
call erase_test_data();
```

Генератор добавляет независимую порцию, ничего не удаляет. Для каждой порции N клиентов/курьеров/категорий/ресторанов, 5N адресов/блюд/заказов/отзывов/платежей, 4N привязок, 10N позиций, 6N выплат. У каждого ресторана пять блюд и пять заказов, два блюда в каждом заказе. Даты заказов ограничены последними 180 днями и шестью месяцами. Увольнение — текущая дата, найм — начало допустимого диапазона. Статусы выбираются через enum_range с допустимыми индексами; минимум один курьер активен. Генерация value<=0 отклоняется. Логины используют UUID порции, телефоны клиентов проверяются перед вставкой, генераторы сериализуются. Категории и адреса имеют метки синтетической порции.

История выплат — шесть завершенных календарных месяцев перед текущим. Заказы распределяются по текущему и пяти предыдущим месяцам, поэтому самый ранний месяц истории может иметь нулевые выплаты. Расчет идет от старого месяца к новому и использует фактические заказы данной порции. Текущий месяц закрывает courier_salary. Месяц определяется по order_timestamp, согласно контракту расчета. Для курьеров без доставок создается нулевая выплата; уволенным коэффициент не обновляется.

Очистка удаляет все записи в порядке, обратном зависимостям внешних ключей. Повторный вызов допустим; схема и ее объекты сохраняются.

## Рейтинг — FOOD-105

Триггер `rating_change()` пересчитывает среднюю оценку ресторана или блюда после вставки, изменения и удаления отзыва. При переносе отзыва пересчитываются оба объекта. Без отзывов результат NULL. У заказа нет отдельного агрегированного рейтинга. Проверки принадлежности объекта описаны в [ограничениях](../constraints.md).

## Зарплата — FOOD-107

```sql
call courier_salary();
```

Повторный courier_salary сохраняет исходный coefficient_used, пересчитывая сумму по актуальным доставленным заказам. Коэффициент следующего месяца вычисляется по количеству доставок. Вызов до конца месяца выполняет предварительный расчет; контракт предусматривает запуск в последний день месяца. Периодический запуск должен обеспечивать внешний планировщик.

Зарплата равна сумме комиссий доставленных заказов за текущий месяц, умноженной на действующий коэффициент. Следующий коэффициент: до 150 доставок включительно — 0.1; 151–250 — 0.2; 251–500 — 0.3; более 500 — 0.5. Для уволенных курьеров коэффициент не обновляется.

## Статистика — FOOD-106

```sql
select * from get_statistic();
```

get_statistic использует одну материализацию доставленных заказов, отдельные группировки стоимости, количества блюд и числа заказов клиента; DISTINCT ON + random() для ничьих. Ресторан без доставок: сумма 0, среднее и лидеры NULL. Среднее возвращается как numeric без принудительного округления; суммы хранятся в копейках.

Колонки: `restaurant_name`, `best_product_name`, `total_amount`, `avg_amount`, `best_user`. Популярность блюда определяется суммой quantity, активность клиента — количеством доставленных заказов.

## Финансовый отчет — FOOD-108

```sql
select * from how_much_money order by year_month;
```

how_much_money строит рекурсивный ряд от первого до последнего месяца доставленных заказов; пустая БД дает пустой результат. При отсутствии доставок суммы заказов и комиссии 0; выплаты берутся фактические, так что при согласованной истории прибыль тоже 0. При наличии выплат в месяце без доставок прибыль равна отрицательной сумме выплат. Первые prev_commission и commission_diff — NULL.

Колонки: `year_month`, `sum_no_commission`, `sum_with_commission`, `commission`, `prev_commission`, `commission_diff`, `courier_pay`, `net_profit`. Чистая прибыль равна комиссии за вычетом выплат курьерам. Предыдущая комиссия определяется через `lag()`.
