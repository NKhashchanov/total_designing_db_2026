# Работа с GitHub: инструкция для итоговой работы

Эта инструкция описывает только работу с Git и GitHub: регистрацию, создание форка, получение проекта на компьютер, сохранение изменений и отправку их на GitHub. При работе с GitVerse алгоритм действий идентичен.

Она не объясняет выполнение SQL, настройку PostgreSQL или создание резервной копии базы данных. Файлы итоговой работы и необходимые шаблоны смотри в исходном репозитории задания.

Исходный репозиторий: https://github.com/NKhashchanov/total_designing_db_2026

## Что должно получиться

В конце работы у тебя должен быть собственный форк исходного репозитория. Именно ссылку на этот форк ты передашь преподавателю.

Пример ссылки:

`https://github.com/ТВОЙ_USERNAME/total_designing_db_2026`

Вместо `ТВОЙ_USERNAME` будет имя твоего аккаунта GitHub.

**Важно:** работай в своём форке, а не в исходном репозитории преподавателя.

## Какой способ выбрать

- **Способ 1 — через браузер.** Подходит, если хочешь выполнять действия на GitHub без команд Git. Файлы можно создавать, редактировать и загружать через веб-интерфейс.
- **Способ 2 — через терминал.** Подходит, если файлы проекта находятся на твоём компьютере и ты хочешь отправлять изменения на GitHub. Ниже команды приведены для Git Bash в Windows; также подойдут macOS и Linux с небольшими отличиями в установке программ.

# Способ 1. Работа через браузер

## Шаг 1. Создай аккаунт GitHub

Если аккаунт у тебя уже есть, переходи к следующему шагу.

1. Открой https://github.com/signup.
2. Зарегистрируйся, указав адрес электронной почты, пароль и уникальное имя пользователя.
3. Выполни инструкции на экране и подтверди адрес электронной почты, если потребуется.
4. Войди в аккаунт на https://github.com/.

Запомни имя пользователя: оно будет частью ссылки на твой репозиторий.

## Шаг 2. Создай форк задания

1. Открой исходный репозиторий: https://github.com/NKhashchanov/total_designing_db_2026.
2. Нажми **Fork**.
3. В качестве владельца выбери свой аккаунт.
4. Оставь название репозитория `total_designing_db_2026`.
5. Если предлагается параметр **Copy the DEFAULT branch only**, оставь его включённым.
6. Нажми **Create fork**.

Подробности: https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo

После создания открой форк. Адрес должен выглядеть примерно так:

`https://github.com/ТВОЙ_USERNAME/total_designing_db_2026`

Убедись, что в адресе указан твой username, а не `NKhashchanov`.

## Шаг 3. Редактируй или создавай файлы

Чтобы создать файл:

1. Открой свой форк.
2. Нажми **Add file → Create new file**.
3. Введи путь и имя файла.
4. Добавь содержимое.
5. Нажми **Commit changes...**.
6. Введи краткое описание изменения.
7. Подтверди коммит кнопкой **Commit changes**.

Чтобы изменить существующий текстовый файл:

1. Открой файл в своём форке.
2. Нажми значок карандаша (**Edit this file**), если редактирование доступно.
3. Внеси изменения.
4. Нажми **Commit changes...**, укажи описание и подтверди сохранение.

**Коммит (commit)** — это запись об изменениях в истории репозитория. Сохранение файла в редакторе само по себе не означает, что изменения сохранены в GitHub: необходимо завершить коммит.

## Шаг 4. Загружай файлы с компьютера

Если файл уже подготовлен на компьютере:

1. Открой свой форк на GitHub.
2. Перейди в каталог, в который нужно поместить файл.
3. Нажми **Add file → Upload files**.
4. Перетащи файлы в область загрузки или выбери их через окно выбора файлов.
5. Проверь список загружаемых файлов.
6. Введи описание изменения и нажми **Commit changes**.

Если нужного каталога ещё нет, создай в нём файл через **Add file → Create new file**. Git не хранит пустые каталоги, поэтому каталог появится в репозитории только после добавления файла.

Учитывай ограничения GitHub на размер загружаемых файлов. Если файл не загружается, проверь сообщение об ошибке и действующие ограничения платформы.

## Шаг 5. Продолжай сохранять изменения

После каждого существенного изменения повторяй процедуру редактирования или загрузки файлов и создания коммита. В описании коммита кратко указывай, что изменилось, например:

- `Добавлены SQL-скрипты`
- `Обновлена документация`
- `Исправлены файлы проекта`

## Шаг 6. Скопируй ссылку для сдачи

1. Открой главную страницу своего форка.
2. Скопируй URL из адресной строки браузера.
3. Проверь, что это твой репозиторий, а не исходный репозиторий задания.
4. Передай ссылку преподавателю способом, установленным для курса.

Пример:

`https://github.com/student123/total_designing_db_2026`

# Способ 2. Работа через терминал

Этот способ предназначен для работы с локальной копией репозитория. Команды ниже приведены для **Git Bash в Windows**. Не вводи символы приглашения терминала — только саму команду.

## Шаг 1. Установи Git

1. Открой официальный сайт: https://git-scm.com/downloads/win.
2. Скачай и запусти установщик Git for Windows.
3. Если не знаешь, какие настройки выбрать, оставь значения по умолчанию.
4. После установки открой **Git Bash** через меню «Пуск».

Проверь установку:

```bash
git --version
```

Если терминал показывает номер версии Git, установка прошла успешно.

Для macOS и Linux инструкции по установке доступны на https://git-scm.com/downloads.

## Шаг 2. Настрой автора коммитов

Выполни команды, подставив своё имя и адрес электронной почты:

```bash
git config --global user.name "Ivan Ivanov"
git config --global user.email "your-email@example.com"
```

Эти данные записываются в историю коммитов. Они не выполняют вход в GitHub.

Проверить настройки можно командой:

```bash
git config --global --list
```

## Шаг 3. Создай форк на GitHub

Даже если дальнейшую работу будешь вести в терминале, форк сначала нужно создать через браузер:

1. Открой https://github.com/NKhashchanov/total_designing_db_2026.
2. Нажми **Fork**.
3. Выбери свой аккаунт и оставь название `total_designing_db_2026`.
4. Нажми **Create fork**.

Открой созданный форк и скопируй его HTTPS-адрес. Он будет выглядеть примерно так:

`https://github.com/ТВОЙ_USERNAME/total_designing_db_2026.git`

## Шаг 4. Склонируй форк на компьютер

**Клонирование (clone)** — это получение локальной копии репозитория с историей Git.

В Git Bash перейди в каталог, где хочешь хранить проект. Например:

```bash
cd ~
```

Склонируй свой форк, подставив его URL:

```bash
git clone https://github.com/ТВОЙ_USERNAME/total_designing_db_2026.git
```

Перейди в созданный каталог:

```bash
cd total_designing_db_2026
```

Посмотри список файлов:

```bash
ls
```

**Важно:** клонируй свой форк, а не исходный репозиторий преподавателя. Иначе у тебя не будет права отправлять изменения в исходный репозиторий.

## Шаг 5. Проверь подключение к удалённому репозиторию

Выполни:

```bash
git remote -v
```

В выводе должен быть адрес твоего форка для получения и отправки изменений. Обычно удалённый репозиторий называется `origin`.

Если указан URL исходного репозитория преподавателя, проверь, тот ли адрес ты использовал при клонировании.

## Шаг 6. Измени файлы проекта

Редактируй файлы в локальной папке `total_designing_db_2026` с помощью удобного редактора.

Например, если установлен Visual Studio Code и команда `code` доступна в терминале:

```bash
code .
```

Если команда не работает, запусти VS Code через меню Windows и выбери **File → Open Folder**, затем укажи папку проекта.

После редактирования сохрани файлы на диске. На этом этапе изменения ещё могут быть только на твоём компьютере.

## Шаг 7. Посмотри, какие файлы изменились

Выполни:

```bash
git status
```

Git покажет новые, изменённые и удалённые файлы.

Чтобы посмотреть изменения в уже отслеживаемых текстовых файлах, выполни:

```bash
git diff
```

Перед коммитом полезно проверить статус и убедиться, что ты собираешься сохранить именно нужные изменения.

## Шаг 8. Добавь изменения в индекс Git

Чтобы подготовить изменения всех файлов в каталоге `db`, выполни:

```bash
git add db/
```

Если ты изменял другие файлы проекта, добавь и их. Команда `git add` подготавливает изменения к коммиту, но ещё не создаёт сам коммит.

Проверь подготовленные изменения:

```bash
git status
```

## Шаг 9. Создай коммит

Выполни:

```bash
git commit -m "Обновлена итоговая работа"
```

Коммит сохраняет подготовленные изменения в локальной истории Git.

Вместо общего описания лучше указывать, что именно было сделано, например:

```bash
git commit -m "Добавлены SQL-скрипты"
```

Если Git сообщает `nothing to commit`, проверь, сохранил ли ты файлы и есть ли новые изменения.

**Важно:** коммит ещё не отправляет изменения на GitHub.

## Шаг 10. Отправь коммиты на GitHub

Выполни:

```bash
git push origin main
```

Команда отправляет локальные коммиты из ветки `main` в ветку `main` твоего форка.

При первом подключении GitHub может запросить авторизацию. При работе через HTTPS обычный пароль аккаунта GitHub для Git-операций не используется. Следуй предложенному способу авторизации, например через браузер или Git Credential Manager.

Если это первая отправка локальной ветки и Git просит настроить upstream, выполни:

```bash
git push -u origin main
```

Если Git сообщает, что ветка `main` не найдена, проверь текущую ветку:

```bash
git branch --show-current
```

Не выполняй команды смены или переименования ветки наугад: сначала проверь, в какой ветке находится твоя работа.

## Шаг 11. Повторяй цикл при дальнейшей работе

После первоначального клонирования не нужно клонировать репозиторий заново после каждого изменения. Используй цикл:

1. Отредактируй и сохрани файлы.
2. Посмотри изменения: `git status`.
3. Подготовь нужные файлы: `git add db/`.
4. Создай коммит: `git commit -m "Краткое описание"`.
5. Отправь изменения: `git push origin main`.

Пример набора команд:

```bash
git status
git add db/
git status
git commit -m "Обновлены файлы проекта"
git push origin main
```

Если коммитить нечего, не создавай искусственные изменения только ради нового коммита. Сначала убедись, что действительно есть новые изменения, которые нужно сохранить.

## Шаг 12. Проверь результат

После успешного `git push` открой свой форк в браузере и обнови страницу. Убедись, что последние изменения появились на GitHub.

В терминале также можно выполнить:

```bash
git status
```

Если все изменения закоммичены, а коммиты отправлены, обычно Git сообщает, что рабочее дерево чистое. Это полезная проверка, но дополнительно убедись в браузере, что изменения действительно присутствуют в удалённом репозитории.

Скопируй ссылку на свой форк и передай её преподавателю:

`https://github.com/ТВОЙ_USERNAME/total_designing_db_2026`

# Частые проблемы

| Сообщение или проблема | Что проверить |
|---|---|
| `git: command not found` или команда не найдена | Установлен ли Git; перезапусти терминал после установки |
| `Repository not found` | Правильно ли скопирован URL и существует ли форк |
| `Authentication failed` | Пройди авторизацию поддерживаемым способом; обычный пароль GitHub не подходит для Git-операций через HTTPS |
| `nothing to commit` | Сохранены ли файлы и есть ли новые изменения |
| `src refspec main does not match any` | Существует ли локальная ветка `main` и создан ли хотя бы один коммит |
| Изменения есть на компьютере, но не на GitHub | Выполнены ли `git commit` и `git push`; не завершилась ли команда ошибкой |
| Не знаешь, в каком репозитории работаешь | Выполни `git remote -v` и проверь адрес `origin` |
